## 文件结构

- `raw/*.json`：**经过最小化处理的检索归档，并非未修改的 API 响应**。保留查询、时间、方法、返回码，入选来源的原始文本字段；未入选项只保留标题、URL 和类型。删除所有 CommentInfoList、头像、热度、权威度和排序字段。
- `sources.json`：研究用主数据，包括取得的文本版本、原样来源 URL、标题、作者、范围、8 个关键词、20 条分析。
- `../dist/data/demo.json`：公开展示数据。用 `npm run prepare:data` 从主数据导出，删除 `texts` 和研究核验字段，保留必要短摘录、AI 概括、上下文及出处。Web 服务的静态文件只开放 `dist/`，不会提供研究归档；新增公开歌曲接口也会裁剪长文本。

## 筛选和分析边界

排除：纯歌词转载、只推荐歌名或一句短评、讨论其他歌或纯概念的内容、未核实作者名称的回答。关于《反乌托邦 pt.2》的文章属于另一作品版本，且含转述评论，不纳入本轮单曲对比。未入选回答不等于没有价值。

8 个角度：情绪共鸣、音乐完成度、歌词意象、自我救赎、现实题材、模仿与同质化、被看见、流量与传播。每个角度至少有一条充分支持其局部概括的真实证据，没有套用缺少来源的候选词。

- 20 条分析中 18 条可支持局部概括，2 条明确标为证据不足。其余组合没有记录，界面显示“当前摘录未涉及”，不说全文没有讨论。
- s1 的“模仿与同质化”保留“原先批评—后来反思”的转折；“被看见”是作者自己的写作经验，不能推及全部 P 主。
- s1 对心灵冲击和流量刺激提出疑问，未证明二者的实际因果；s3 的音乐评价在可取得搜索段落中不完整，所以不依据 Summary 补造原句。
- s4 中的“我”是作者解读的歌词主体，不是回答作者经历；歌词解读不是歌曲作者意图的核实。
- 关于算法、受众和流量的解释归属于相应作者，没有独立核验。歌墙不按热度或权威度判断观点高下。
- 有关“今年”“当前”的描述依原作者写作语境理解，不能直接替换成 2026 年现状。
- 无评论进入分析或展示；长文阅读引导至知乎原文。每行是这篇内容的表达，不是作者人格画像。

当前样本能演示阅读发现，但不是系统性文献检索或整个社区的代表性样本。没有采集点击或关系数据，不能把外链点击宣称为人际连接或社区闭环。

## 彩色关键词墙的计数

按后续交互要求，字号改为对应词语在已收录摘录中的出现次数驱动；不同颜色用于视觉区分。由于展示词中有归纳标签，本项目**不是仅统计标签全称的逐字出现**，而是公开对应的精确匹配词表。例如“音乐完成度”计入“作曲、编曲、音乐性、混音、编混、音乐制作水准”。详情列出实际命中词和次数，不用模型虚构一个热度值。

任意歌名由本地服务按需调用 `search zhihu`，并按歌曲指向、可署名、至少 140 字的取得文本、文章／回答类型和合法原始 URL 筛选。最多 6 篇，按 URL 去重，忽略评论。保留查询、检索时间、原始摘录与覆盖范围。动态歌曲的身份元数据标记为用户检索主题，不假定来自已核验音乐目录。

新文本由 `prompts/runtime-analysis.md` 约束分析；每个 AI 引用必须逐字位于其对应来源，且包含关键词匹配词。无效格子舍弃，不补齐稀疏矩阵。逐字校验不等同于人工核验语义与立场。分析不可用时，基于本地中文分词与实际词频生成可点击词墙，展示明确标记的自动原句预览；这些条目的观点证据为 insufficient，不编造作者结论。

每篇只对一份取得文本计数，匹配词、次数和位置可回溯。成功结果存入 `runtime/song-*.json`，公开 API 去除完整文本与排除记录。缓存中不保存凭证。当前 runtime 中没有新歌曲缓存；测试的成功检索路径使用历史真实材料和隔离临时目录，不属于线上新增数据。
