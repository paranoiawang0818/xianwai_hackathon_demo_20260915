## 启动

使用 Node.js 18 或以上，在本目录运行：

```sh
npm start
```

打开 <http://127.0.0.1:4173>。无运行依赖，无须 npm install 或构建。端口占用时使用 `PORT=4174 npm start`，Ctrl+C 停止。需要使用这个 Node 服务，普通静态服务器不提供歌曲检索接口。

已有歌曲的阅读不依赖外部 API。新增歌曲需要联网，并由服务端调用本机已安装、已配置凭证的知乎 CLI。默认路径位于 `~/Library/Application Support/zhihu-cli/current/zhihu-cli`；换机器时可通过 `ZHIHU_CLI_PATH` 指向已确认的安装。凭证留在本机钥匙串，不进入浏览器或数据文件。若沙箱中提示认证不可用，先检查服务运行环境和钥匙串访问，不要直接重装或重新设置凭证。

## 使用

1. 输入歌名；为减少同名误匹配，推荐“歌名 - 创作者”，也可点击三首预设。缓存立即返回，其他输入进入真实检索流程。
2. 等待区域显示查缓存、检索、筛选、整理四个阶段；动画只表示当前仍在处理，不伪造完成百分比。可以取消；迟到响应不会覆盖新操作。
   首次打开、搜索已整理歌曲、进入任何缓存歌墙也有声波与流动条，随后平滑展开内容。缓存过渡约 0.5–0.7 秒；读取较慢时持续等待真实响应。系统选择减少动态效果时关闭动画与额外过渡等待。
3. 点击歌曲结果进入彩色词墙。词频越高字号越大，详情列出计数词表与次数。点击词只查看，详情中的“加入对比”才改变选择。
4. 选择 2–5 个词后比较；点击观点查看原句、上下文和出处。五列可横向滚动，标题作者列与表头固定。
5. 查看知乎原文；返回调整选择。不同歌曲分别保存选择，避免串用观点。当前标签页刷新后仍保留状态。

没有足够材料、额度不足、接口失败分别提示，不把请求失败当成“知乎没有讨论”。原文在新页面打开，是否能读到正文取决于网络和知乎访问策略。

## 数据与分析

关键词与来源是多对多关系。同一篇可以对应多个词，同一段也可以支持几个角度；每个“来源 × 关键词”格子单独保留概括、最合适的一段短引文和上下文。词频只用于字号，不直接决定观点分类。当前不是全文逐段的穷尽分析：摘录范围有限，也可能存在尚未提取的关联，因此空格表示“当前未整理到对应证据”。表格每行可展开查看这篇内容的所有已整理角度，蓝色标记本次选择的词。

进入或刷新对比页会显示约 0.65 秒的声波、流动条与表格骨架，再平滑展开表格；加载时可返回调整，保留选择。减少动态效果时跳过等待和动画。验证脚本：`tests/comparison-loading.mjs`。

服务端按用户输入搜索，保留有署名、文本足够且明确涉及该歌曲的文章／回答，排除评论、纯歌词、无关概念及重复 URL。每次最多保留 6 篇，不凑固定行数。搜索 ContentText 是摘录，不是全文。

取得文本后，使用已配置 CLI 的直答能力按 `prompts/runtime-analysis.md` 整理关键词与局部观点。引用必须逐字命中对应来源，来源 URL 和作者只能来自搜索结果。模型输出不通过校验、超时或额度不足时，退回**原句预览 · 自动截取**模式，标记观点待核验，不把截取文字冒充 AI 概括或作者最终结论。逐字校验不能保证自动语义分析绝对正确，完整理解仍需回到原文。

三首预设都经过准备阶段的逐条证据与语境核验；其他动态新歌的自动分析有单独模式标记。搜索和直答分别消耗对应 API 额度。额度为零时停止业务请求；额度结果最多缓存 5 分钟，过期后的手动搜索会重新核验，因此提额后不必强制等到第二天。不定时轮询或循环重试业务请求。

成功整理的歌曲存入 `data/runtime/song-*.json`，重启服务后仍可使用。这里只保存取得的文本、出处和分析，不保存凭证。公开 API 删除长文本归档，只返回必要短摘录和展示字段；原始研究文件不由 Web 服务开放。

## 文件

- `dist/`：原生 HTML/CSS/JS；`dist/data/demo.json` 为预先核验的单曲展示数据。
- `data/catalog.json`：三首预设及其状态；`data/sources.json`、`data/raw/`：原有真实研究归档；`data/README.md`：来源与覆盖说明。
- `data/runtime/`：两首新歌的真实缓存、实际额度状态。目录接口合并这些缓存与预设配置。
- `scripts/serve.mjs`：仅监听本机的 HTTP 与 SSE 服务；`search-service.mjs`：查询、缓存、分析与错误状态；`zhihu-provider.mjs`：已确认 CLI 的服务端适配；`song-data.mjs`：过滤、证据校验、词频与公开数据裁剪。
- `prompts/extract-keywords.md`、`compare-perspectives.md`：准备阶段的可复用规则；`runtime-analysis.md`：运行时结构化分析约束。

更新人工核验数据后执行 `npm run prepare:data`，重新统计词频并导出公开 JSON；这个命令不调用 API。各关键词的精确匹配词表公开可查，重复检索同一来源不增加频次；次数只代表取得的摘录，不是知乎全站热度或赞同票数。

## 限制

两首新歌已实际在线检索；《白石溪》在线分析成功，《I LOVE U》未通过自动分析校验后正常退回原句预览。最终三首预设均在准备阶段复核。自动过滤与分析仍可能遗漏内容或误解上下文；同名歌建议补充作者。搜索不是完整曲库目录，也不承诺全文获取或穷尽讨论。没有登录、发布、评论、聊天、关注、音频播放或后台管理；未部署、报名、提交作品。外链阅读只代表进一步阅读的入口，不代表已建立人际连接或社区闭环。

## 复现本轮整理

`data/raw/song-*-initial.json` 保存新歌首次取得的文本与初始结果，`white-more.json`、`dystopia-more.json`、`love-more.json`、`love-context.json` 保存补检索记录。下面的命令只处理已取得的真实文本，不调用 API；重启服务后加载新缓存。

```sh
node scripts/expand-keywords.mjs
node scripts/review-presets.mjs
node scripts/diversify-sources.mjs
npm run prepare:data
npm run validate
```
